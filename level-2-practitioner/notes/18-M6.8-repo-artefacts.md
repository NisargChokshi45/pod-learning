# M6.8 — What Claude writes down in the repo

| Status | Audience | Hours | Prerequisite |
|---|---|---|---|
| ELECTIVE | Clusters A, C, D, E (cluster letters are **undefined in source**) | 1.5 | M6.2 |

**Objective:** decide, as a team, what gets written into the repository when Claude works on it, so that six
months later anyone can reconstruct what was done and why.

> **Why this is a module, not a footnote.** Agentic coding generates judgement calls faster than any commit
> message can capture them: approaches tried and rejected, assumptions made, trade-offs taken. Teams that
> don't decide where those go end up with **nothing** (the reasoning lived in a chat that's gone) or **an
> unreadable pile** (everything dumped into CLAUDE.md). This module fixes the convention. Most of it is
> a *team agreement*, not a product feature. The only `[code]` claims are the file locations and switches.

---

## TL;DR

- **Five artefacts, five jobs:** `CLAUDE.md` (humans instruct Claude) · auto memory (Claude's private
  notes, not committed) · `docs/worklog/` (one file per fix or judgement call, append-only) ·
  `docs/adr/` (decisions that bind future work) · `MISTAKES.md` (human corrections only, kept short).
- **CLAUDE.md ≠ auto memory.** The first is reviewed instructions, committed. The second is per-machine,
  unreviewed, self-contradicting notes. **Never commit auto memory.** Promote what's worth keeping.
- **Worklog:** `docs/worklog/YYYY-MM-DD-short-slug.md`. It records the symptom, what was investigated, what was
  rejected and why, what was chosen, and what remains uncertain. Claude drafts it; a human reviews it before commit.
- **ADR:** context, options, decision, consequences, status. Numbered. **Superseded, never deleted.** An ADR
  binds future work. A worklog entry explains past work. **The decision is never delegated.**
- **MISTAKES.md:** what Claude got wrong, plus the instruction that would have prevented it. When it grows,
  the entries become `.claude/rules/` and leave the file.
- **Audit trail:** `intent.md` → `spec.md` → `plan.md` are committed, so the reasoning ships with the code. A stale
  `plan.md` is worse than none.
- **Commit** CLAUDE.md, `.claude/{rules,skills,agents}/`, `.claude/settings.json`, `.mcp.json`, `docs/`.
  **Ignore** `.claude/settings.local.json`, auto memory, `CLAUDE.local.md`, and anything with a credential.

## Concepts

### 1. Five different artefacts, five different jobs

| Artefact | Who writes it | What it holds | Lifespan |
|---|---|---|---|
| `CLAUDE.md` | Humans | Instructions to Claude: commands, conventions, boundaries | Long-lived, edited deliberately |
| Auto memory (`~/.claude/projects/<project>/memory/MEMORY.md`) | Claude | Claude's own working notes about the project | Disposable, machine-local, not committed |
| `docs/worklog/` | Claude, reviewed by a human | One file per fix or judgement call: what was wrong, what was tried, what was chosen | Permanent, append-only |
| `docs/adr/` | Humans, drafted with Claude | Architecture decisions: context, options, decision, consequences | Permanent, superseded not deleted |
| `MISTAKES.md` | Humans only | Corrections a human had to make to Claude's work | Permanent, deliberately short |

**The failure mode this prevents:** everything goes in CLAUDE.md until nobody reads it. A 600-line
CLAUDE.md costs tokens in every session (M6.2), buries the five rules that matter, and mixes instructions
("use `Decimal`") with history ("in March we tried floats and…"). History belongs in the worklog. Decisions
belong in ADRs. Only standing instructions stay in CLAUDE.md.

### 2. CLAUDE.md versus auto memory

- **Direction of travel:** CLAUDE.md is **you instructing Claude**. Auto memory is **Claude noting things
  for itself** [code] GA.
- **Auto memory is on by default and lives outside the repository**, under `~/.claude/projects/…`. It isn't
  shared with teammates, isn't reviewed, and isn't a record. Worktrees of the same repo share it on one
  machine. Other machines never see it.
- **Why you don't commit auto memory:** it's per-machine (your laptop's notes differ from CI's), it's
  unreviewed (nobody checked that it's true), and **it will contradict itself** over time, because notes
  written on different days about a changing codebase disagree. Committing it would turn private guesses into
  shared instructions without review.
- **Turning it off where policy requires** (for example client NDAs that forbid unreviewed persistence): `/memory`
  (toggle), `"autoMemoryEnabled": false` in settings, or `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` in the
  environment. Put the setting in the committed `.claude/settings.json` if it's a repository policy.
- **What to promote, and how to notice:** open `MEMORY.md` during the quarterly prune (§8) or when a
  session surprises you. Promote a note when it's **true, stable and useful to everyone**. For example,
  "integration tests need `docker compose up -d db` first" becomes a CLAUDE.md command line. "Files under
  `src/legacy/` use tabs" becomes a path-scoped rule. Delete notes that are wrong or personal.

### 3. The worklog: `docs/worklog/`

- **One file per fix or judgement call.** Not one per commit (too granular) and not one per day (it mixes
  unrelated reasoning).
- **Naming:** `YYYY-MM-DD-short-slug.md`, for example `2026-11-20-refund-rounding.md`.
- **Contents:** the symptom; what was investigated; **what was rejected and why**; what was chosen;
  **what remains uncertain**.
- **Who writes it:** Claude drafts it at the end of the task, from the session it just ran. A human
  reviews it before commit, for accuracy above all.
- **Why append-only:** a worklog you edit is a worklog you can't trust. If an entry turns out wrong, add
  a new entry that corrects it and links back.
- **What it's for:** the next person debugging the same area, and the reviewer who asks "why is it done
  this way?".

```markdown
# 2026-11-20 — Refund totals off by one cent

**Symptom:** ~0.4% of partial refunds were 1 cent short vs the ledger (BILL-431).
**Investigated:** rounding in `refunds.py` (HALF_EVEN), currency conversion order, DB column precision.
**Rejected:** switching to HALF_UP globally — changes invoice totals too; would need finance sign-off.
**Chosen:** round each line item *after* currency conversion, not before (commit a1b2c3d). Test
`test_partial_refund_rounding` reproduces the 12 historical cases.
**Uncertain:** whether the 3 JPY refunds from October need back-correction — asked finance (open).
Drafted by Claude; reviewed by: <name>, 2026-11-21.
```

### 4. ADRs: `docs/adr/`

- **The standard shape:** context, options considered, decision, consequences, status (Proposed ·
  Accepted · Superseded by ADR-NNNN).
- **Numbering:** `0001-…`, `0002-…`, never reused. **Superseding rather than deleting:** the old ADR stays.
  Its status changes to "Superseded by 0014", and 0014 links back. The history of *why we changed our
  minds* is part of the record.
- **The line between an ADR and a worklog entry:** an **ADR binds future work** ("all services publish
  events via the outbox"). A **worklog entry explains past work** ("why this bug was fixed this way"). If a
  worklog finding should constrain future changes, promote it to an ADR.
- **Drafting with Claude, deciding as a human:** Claude is good at drafting options and consequences
  (authoring is covered in M5.1). **The decision is never delegated.** The ADR names the deciders.

```markdown
# ADR-0007: Use the transactional outbox for domain events

Status: Accepted (2026-11-18) · Deciders: <tech lead>, <architect>
## Context
Order and payment services publish events after DB commits; we lost events on crashes twice (see
worklog 2026-10-02-lost-order-events).
## Options considered
1. Publish after commit (status quo) — simple; loses events on crash.
2. Transactional outbox + relay — exactly-once to the relay; extra table and process.
3. CDC from the DB log — no app changes; new infra the team hasn't run.
## Decision
Option 2. Team already runs the relay pattern in billing; CDC deferred.
## Consequences
+ No lost events. − Extra table per service; relay must be monitored. Revisit if event volume > 5k/s.
```

### 5. MISTAKES.md

- **Human corrections only. Claude doesn't write to this file.** Say so in CLAUDE.md ("Never edit
  MISTAKES.md"), and consider a deny rule (M6.4).
- **What goes in:** something Claude got wrong that a human had to fix, **and the instruction that would
  have prevented it**.
- **Why it's restricted to humans:** the value is the *human's judgement* that something was wrong. If
  Claude logged its own mistakes, the file would record what Claude noticed, which excludes exactly the errors
  it didn't notice.
- **Deliberately short.** When it grows, each entry becomes a rule in `.claude/rules/` (or a CLAUDE.md
  line) and **leaves the file**.
- **Feedback loop and cadence:** review it at each sprint retro. Promote the entries that recur, and delete
  the ones a rule now covers.

```markdown
# MISTAKES.md — human corrections to Claude's work (humans only)

- 2026-11-12 · Claude added `requests` to a service that standardises on `httpx`. → Rule: "HTTP clients
  use httpx (see app/http.py)". *Promote to .claude/rules/http.md if it recurs.*
- 2026-11-19 · Claude "fixed" a flaky test by adding `sleep(2)`. → Rule: "Never add sleeps to tests;
  wait on a condition or fix the race."
```

### 6. The committed audit trail: `intent.md`, `spec.md`, `plan.md`

| File | Holds | Written | Maps to the loop (M6.2) |
|---|---|---|---|
| `intent.md` | What we're trying to achieve, and for whom | **First**, before anything else | Before explore |
| `spec.md` | What the thing must do: testable statements | After intent | Before explore. It defines "verify" |
| `plan.md` | How it will be done: the sequence agreed before implementation | From plan mode | Plan |
| *worklog entry* | What actually happened | After verify | After verify |

- **Commit all three**, so the reasoning ships with the code. The reviewer reads intent → spec → plan → diff.
- **Where they live:** alongside the feature (`features/csv-export/intent.md`) or under
  `docs/features/<name>/`. **Decide once per repository** and write it in CLAUDE.md.
- **Keeping them honest:** a `plan.md` that no longer matches the code is **worse than none**, because it
  misleads with authority. When implementation deviates, update the plan in the same PR, or record the
  deviation in the worklog.

```markdown
<!-- intent.md --> Finance analysts need to export monthly invoice data to reconcile in Excel without
asking engineering. Success = they stop filing export tickets.
<!-- spec.md --> 1. GET /reports/invoices.csv?month=YYYY-MM returns RFC 4180 CSV. 2. Only users with
`reports:read`. 3. Amounts in minor units with currency column. 4. ≤ 100k rows or 413 with guidance.
<!-- plan.md --> 1. Reuse ReportQuery; add CsvRenderer (stdlib csv). Test: test_csv_shape. 2. Permission
guard. Test: test_forbidden_without_scope. 3. Row cap + 413. Test: test_row_cap.
```

### 7. What to commit and what to ignore

**Committed:** `CLAUDE.md`, `.claude/rules/`, `.claude/skills/`, `.claude/agents/`, `.claude/settings.json`,
`.mcp.json`, `docs/` (worklog, ADRs, feature trios), `MISTAKES.md`.
**Ignored:** `.claude/settings.local.json`, auto memory (it's outside the repo anyway), `CLAUDE.local.md`,
anything containing a credential.

```gitignore
# Claude Code — personal / machine-local
.claude/settings.local.json
CLAUDE.local.md
# secrets never committed (also scan in CI)
.env
.env.*
*.pem
```

> **Syllabus says:** commit `.claude/settings.json`, `.mcp.json`, `.claude/{rules,skills,agents}`; ignore
> `settings.local.json`. · **Current (verified 2026-11-28, code.claude.com/docs/en/settings, …/memory):**
> confirmed for settings.json, `.mcp.json` and CLAUDE.md. Claude Code adds `.claude/settings.local.json` to your
> *global* git excludes the first time *it* creates the file, but a hand-made one isn't covered. **`CLAUDE.local.md`
> is not auto-ignored.** Add both to the repo's `.gitignore` yourself, so every clone is safe.

**The review question for every new file:** *would a new joiner be helped or confused by this?*

### 8. Review discipline

- **Review a worklog entry like code:** is it **accurate** (does the commit actually do what it says)? Is it
  **useful** (would it save the next person an hour)? Is it **honest about uncertainty** (does "Uncertain"
  say something, or is it empty to look tidy)?
- **A quarterly prune:** promote recurring MISTAKES to rules; move superseded guidance out of CLAUDE.md;
  supersede stale ADRs; check `plan.md` files against the code; read auto memory for anything worth promoting.
- **The anti-pattern:** documentation nobody reads, generated because a hook required it. A hook that
  forces a worklog file on every commit produces hundreds of empty "Symptom: n/a" entries. Require entries
  for *judgement calls*, and review them.

## Under the hood

### Why the split works: read paths

| Question someone asks later | Where they look | Why that file answers it |
|---|---|---|
| "How should I (or Claude) work here?" | CLAUDE.md, `.claude/rules/` | Loaded automatically, short, current |
| "Why is this code like this?" | `git log` → worklog entry | Linked from the commit, written at the time |
| "Are we allowed to do X?" | `docs/adr/` | Binding decisions, with status |
| "What does Claude keep getting wrong?" | MISTAKES.md | Human-curated, short |
| "What was this feature *for*?" | `intent.md`, `spec.md` | Written before the code |

Each artefact has **one reader and one question**. Mixing them makes every question harder to answer.

### Why auto memory contradicts itself

Auto memory is appended across sessions, each written from that session's partial view. Monday's note
("the API uses v1 auth") and Thursday's note ("auth moved to v2") can both be present. Nothing reconciles
them, because no human reviews the file and there's no "supersede" mechanism. Only the first ~200 lines
load, so which note "wins" can depend on position. That's tolerable as private scratch, and unacceptable as
a shared record.

### Linking the trail

Put the worklog filename in the commit body (`Worklog: docs/worklog/2026-11-20-refund-rounding.md`) and the
ADR number in the PR. `git log --grep "Worklog:"` then becomes an index of reasoning, and audit evidence
for AI-assisted development is a query, not an archaeology project.

## In production

**1. Client handover at engagement end**
*Situation:* after a 9-month engagement, the client's team takes over the repo.
*Right move:* handover includes the ADR index, the worklog, intent/spec/plan per feature, and a pruned
CLAUDE.md. Auto memory stays on your machines. It was never theirs or yours to ship.
*Failure mode:* "the reasoning is in our Claude chats". Those are inaccessible to the client, and may not be retained.

**2. "Why was it built this way?", eighteen months later**
*Situation:* an auditor asks why refunds round after conversion.
*Right move:* `git blame` → commit → `Worklog:` link → the entry, with the rejected alternative and the reviewer's name.
*Why:* the answer was written down at the time, by the people who knew.

**3. Onboarding a developer to an unfamiliar repository**
*Right move:* read CLAUDE.md, then the accepted ADRs, then the last month of worklog. The new joiner learns the
standing rules, the binding decisions and the recent history in an afternoon.

**4. The hook that generated noise**
*Situation:* a team added a hook requiring a worklog file per commit. Three months later there were 900
entries, mostly empty.
*Right move:* remove the per-commit hook. Require an entry for judgement calls, and make it part of PR
review ("does this PR need a worklog entry?").

**5. Audit evidence for AI-assisted development**
*Situation:* the client's compliance team asks how AI-written code was controlled.
*Right move:* show plan.md approval, reviewed diffs, worklog entries with human reviewer names, MISTAKES →
rules history. Every step has a named human (M8.3).

## Pitfalls

| Anti-pattern | Why it bites | Do instead |
|---|---|---|
| Everything in CLAUDE.md | Token cost every session; rules buried | History → worklog; decisions → ADR; rules → `.claude/rules/` |
| Committing auto memory | Unreviewed, machine-specific, self-contradicting notes become "team truth" | Keep it local; promote reviewed facts |
| Editing old worklog entries | The record can no longer be trusted | Append a correcting entry that links back |
| Deleting a superseded ADR | Loses why the team changed its mind | Mark Superseded; link the new one |
| Claude writing MISTAKES.md | It records only the errors Claude noticed | Humans only; enforce it in CLAUDE.md or a deny rule |
| Stale `plan.md` | Misleads with authority | Update it in the same PR, or record the deviation |
| `CLAUDE.local.md` not in `.gitignore` | Personal paths or notes leak into the shared repo | Add it to the repo `.gitignore` |
| Hook-mandated docs per commit | Volume without value; nobody reads it | Entries per judgement call, reviewed in PR |

## Hands-on exercises

1. **Set up the full convention** in a sandbox repository: `CLAUDE.md`, `.claude/rules/`, `docs/worklog/`,
   `docs/adr/`, `MISTAKES.md`, and the intent/spec/plan trio. Write the `.gitignore`.
   **Done when:** a fresh clone shows every committed artefact, `git check-ignore` confirms
   `.claude/settings.local.json` and `CLAUDE.local.md` are ignored, and CLAUDE.md says where feature trios
   live.
2. **Fix a seeded bug and write the worklog entry.** A peer reviews it for accuracy and usefulness, not style.
   **Done when:** the entry has all five parts, "Rejected" names at least one alternative with a reason, and
   the peer confirms that every claim matches the commit.
3. **Convert three real past decisions into ADRs**, including one that was later superseded.
   **Done when:** three numbered ADRs exist, the superseded one still exists with status "Superseded by
   ADR-NNNN", and each names its human deciders.
4. **Take three entries from a provided MISTAKES.md and turn them into path-scoped rules.** Show the rule
   firing.
   **Done when:** each rule has `paths:` scoping, the entries have left MISTAKES.md, and a session that
   touches a matching file follows the rule (shown in the transcript).
5. **Audit a provided repository** against the convention and list what's missing or misfiled.
   **Done when:** your list classifies every finding (missing / misfiled / stale / should-not-be-committed)
   and proposes the fix for each.
